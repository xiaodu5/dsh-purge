## 0. 结论摘要（先给判断，后给证据）

1. **它不是"配置型插件"，而是"就地改写宿主"的注入器**：82 条字符串补丁直接改宿主 `node_modules`/`app.asar` 内的源码（`ALL_PATCHES.length = 82`，id 1–88，分层：提示词 25 / 代码 46 / 工具 8 / 兼容 3），再叠一条 shim 注入（`dsh.cmd|ps1|无扩展名`）与一份 21,194 字符的系统提示词。自述是"破甲"（prompt override），实质是对宿主 **提示词层 + 审批层 + 沙箱层** 的运行时夺权。
2. **两条主线并行**：①`lib/core.js`(7984 行) 的文件补丁引擎 + `lib/identity.js`(987 行) 的装配改写；②`lib/redteam/*`(17 个模块 16,678 行) 的红队演练台（SQLite 状态机 + 56 个工具 + 25 条评分规则 + 1086 行报告生成）。
3. **工程成熟度 = 功能成熟 / 工程幼稚**：0 运行时依赖、0 lint、单一 CI 且镜像仓库下 CI 永久空转（`.github/workflows/release.yml:17` 的 `if: github.repository == 'YuJunZhiXue/dsh-purge'` 对 `mmparko/dsh-purge` 恒假）；4 个文件占全仓 50.1% 代码量（`client.js` 8736 / `core.js` 7984 / `redteam/store-core.js` 5385 / `redteam/client.js` 4218）。（两轮优化后：`scripts/selfcheck.mjs` 11 项 + `test-report-replay.mjs` 18 例回归已就位，见 `06/07`；lint 与 CI 空转仍在）
4. **版本契约靠字符串猜**：无任何宿主版本校验，兼容性由"补丁命中/未命中"隐式表达。本机已有实证——红队 56 个工具在 `dsh 0.2.0-rc.2` 上**注册失败**：`~/.dsh/redteam/preset-declare.json` → `"broken": "redteam-tools (dsh-purge/redteam/tools): unsupported JSON schema: parameters.parameters.additionalProperties must be explicitly true or false"`，状态 `registered-broken`。
5. **最大风险不是"红队功能"，而是"不可审计的提示词 + 无签名的自动更新 + 静默删系统计划任务"**：提示词是仓库内密钥可解的 AES-256-GCM 密文（混淆非保密）；更新包无哈希/签名（`lib/update.js:878-914`）；`Apply` 每次都会删掉无关组件 DSH Doctor 的计划任务与脚本（`lib/core.js:1162-1207`）。

## 4. 提示词与身份系统

**出厂提示词的真实链路**：`lib/default-prompt-inject.md`（不进发布包）→ `scripts/embed-default-prompt.mjs:7-8` `sealSlot()` → `lib/asset-table.js`（96 字符一行的 base64）→ 运行期 `lib/table-read.js:6-17` `openSlot()` 解密 + inflate → `lib/core.js:7597-7601` `defaultOverrideText()`。密钥由仓库内常量派生（`lib/table-key.js:11-13`，`MIX` 含 `"cordis.slot.v2"` + `"dsh-purge"` 字符码 + `"surface:web|desktop"` + `"ov.table.1"`，sha256 后配 mask），算法 AES-256-GCM + deflate-9。

- **实测**：本机解密得到 **21,194 字符**，以 `<|im_start|>system:<project_instructions>` 开头（ChatML 信封），尾部 `House Rules`；装配时用 `peelChatmlEnvelope`（`lib/identity.js:62`）剥信封。
- **失败即静默**：`openSlot()` 任何异常 `return ""`（`:6-17`）→ 注入链降级为"无注入"，界面只显示 `override_status: missing`，无告警。
- **四级读取优先级**（`lib/index.js:220-242`）：进程内 committed override → hung operator prompt → 磁盘 `$DSH_HOME/prompt-inject.md` → 加密槽默认；`lib/rules.js:243-257` 是同一套的另一份实现（两处必须手工同步，`lib/core.js:7722-7724` 注释记录了历史 bug）。
- **改稿归属判定按内容特征**：`PLUGIN_DEFAULT_MARKS = ["<|im_start|>system:","<project_instructions>","Little Code Sauce"]`，同时命中即视为"插件血统"可被静默覆盖（`lib/core.js:7656-7667`），用户基于旧默认的手改稿会被吃掉。
- **装配流水线**（`lib/identity.js:901-987`）：逐段丢弃 `harness:identity`/mnemon/workspace baseline → 非插件段一律 `stripChatmlTags(stripHarnessPersona(text))`（官方人设在此被抹掉）→ `modePromptText`（红队砍掉 CTF 段、删免责话术段）→ `escapeDshInterpolation(peelChatmlEnvelope(adaptInjectForMinimalPreset(withOwnServers(...))))` → 前置 `dsh-purge`(-100000) 与 `dshpg-capabilities`(-99999) → `leadWithInject` 从其他段正文中**删除重复注入**再置顶 → 尾部 80 字符 needle 自检兜底。
- **注入向量白名单**：`DSH_INTERPOLATE_ALLOWED = {cwd, model, provider}`，其他 `{{...}}` 一律转义（`lib/identity.js:11,23`）。

**红队/官方两套正文**由 agent preset 分流（`lib/identity.js:450-512`，含子代理继承：`header.origin==="subagent"` → 跟父会话）。**"按模型换提示词"是营销口径**：`lib/` 全目录 `modelId|perModel|profileByModel` 0 命中；真正的"模型适配"是改宿主 provider 实现文件（§3 三条补丁）。
