## 1. P0-1：红队工具注册失败

### 1.1 根因链（全部有代码行号）

| 环节 | 证据 |
|---|---|
| 宿主把工具参数当**属性表**编译 | `@deepseek-ai/dsh-tools/lib/index.js:802-803`：`parameterSchemaSpecToJsonSchema(spec)` → `compilePropertyMap(spec, "parameters")`（路径前缀就是 `parameters`） |
| 校验器要求显式布尔 | 同包 `lib/index.js:699` = `lib/types/schema.js:156-160`：`if (!Object.hasOwn(input,'additionalProperties') \|\| typeof input.additionalProperties !== 'boolean') authorError(\`${path}.additionalProperties must be explicitly true or false\`)` |
| 路径为什么是 `parameters.parameters` | 属性表里有个**参数名叫 `parameters`** 的自由对象 → 路径拼接成 `parameters.parameters` |
| 为什么"全军覆没" | 注册是 fail-fast：`preset-declare.json` 只留一句 `broken: "unsupported JSON schema: parameters.parameters.additionalProperties must be explicitly true or false"`，`phase: "registered-broken"` |
| 为什么仓库里搜不到 | 报错来自 **1.1.73**（线上），仓库是 **1.1.71**；漏写的 5 处是 1.1.72/1.1.73 新增的：线上 `lib/redteam/tools.js:2060,2061,2093,2094,2122` |

### 1.2 复现（逐字，真宿主真校验器）

```

PS> node "C:\...\dsh-purge优化\scripts\e2e-tool-schema.mjs" "C:\Users\13248\.dsh\profiles\web\node_modules\dsh-purge\lib\redteam\tools.js"
```

这条输出与 `~/.dsh/redteam/preset-declare.json` 里的 `broken` 字段**逐字一致** —— 根因闭环，不再是推测。

### 1.3 修法：注册前归一化（一处修，全批好）

新增 `lib/redteam/param-schema.js`：

| 导出 | 行 | 作用 |
|---|---|---|
| `FREE_FORM_ADDITIONAL_PROPERTIES = true` | 25 | 缺省补 `true`（自由 JSON 对象语义），不是 `false` |
| `withExplicitAdditionalProperties(definition, {onFill})` | 71 | 深走 `parameters` 属性表 → `properties` / `items` / `oneOf`，凡 `type:'object'` 且 `additionalProperties` 不是布尔就补 `true`；返回副本，不改入参；幂等 |

**为什么补 `true` 而不是 `false`**：这些节点本来就是"任意 JSON 对象"（如 `parameters`/`result`/`verified_result` 之类要参与哈希的自由结构）。补 `false` 会在**运行期**把模型多传的键判成非法 —— 那是把"注册失败"换成"调用失败"，更糟。已显式写好的（`names`/`ports`/`fingerprints` 的 `false`）原样保留。

`lib/redteam/tools.js` 只动两处：

```js
// :24
import { withExplicitAdditionalProperties } from './param-schema.js'

// :83 / :97-105
const rawDefineTool = loadDefineTool()
let warnedSchemaFill = false
const defineTool = (definition, ...rest) =>
  rawDefineTool(withExplicitAdditionalProperties(definition, {
    onFill: (paths) => { /* 每个进程只 warn 一次，提醒回源修 spec */ },
  }), ...rest)
```

56 个 `defineTool({...})` 调用点**一行没改**（包装函数值而不是改 56 处），`withStructuredErrors(defineTool({...}))` 的既有形状不变。

### 1.4 验证

| 对象 | 命令 | 结果 |
|---|---|---|
| 仓库 1.1.71 | `e2e-tool-schema.mjs lib/redteam/tools.js` | `OK … registered 56 tools, 56 unique names` |
| 线上 1.1.73（打同一份归一化） | `e2e-tool-schema.mjs <installed>/lib/redteam/tools.js` | `OK … registered 64 tools, 64 unique names` |

### 1.5 遗留判断

归一化层是**兜底**，不是免罪符：spec 该写全还得写全（`selfcheck.mjs` 第 2 项就是为了逼这件事）。但两者定位不同 —— 静态扫描管"我们自己写的"，归一化层管"宿主下次又加一条新契约/新工具忘了写"。1.1.73 的教训是：**fail-fast + 无告警**，一条漏写 = 64 个工具静默消失，所以兜底层必须存在。

## 2. P0-2：迁移里的两个悬空引用（新发现第二个）

原判断只提 `LEGACY_STAGE_MAP`（`schema.js:586`）。实际读代码发现同一个 `catch{}` 里还有 **`SCOPE_SQL`**（原 `:591`）：

```js
// 改前（1.1.71）
if (ensure('attack_step', 'stage_code', 'TEXT')) {
  try { for (const [legacy, code] of Object.entries(LEGACY_STAGE_MAP)) stmt.run(code, legacy) } catch {}
}
try { db.exec(`UPDATE asset SET scope = (${SCOPE_SQL}) WHERE scope IS NULL OR scope = ''`) } catch {}
```

`schema.js` 只 import 了 `DatabaseSync` 与 `parseTargetPort`（`:1-4`），两个标识符都在 `store-core.js`（`LEGACY_STAGE_MAP:355`、`SCOPE_SQL:154`），而 `store-core` 依赖 `schema.js` —— 反向 import 会成循环。于是两个 `try` 每次都抛 `ReferenceError` 再被自己吞掉：

- 「历史 `attack_step.stage` → `stage_code`」回填**从未执行**；
- 「`asset.scope` 按 IP 自动判内外网」回填**从未执行**（这直接影响计分口径 `internal/external` 与报告里"内网/外网"的统计）。

修法（依赖注入，最小面）：

```js
// schema.js:474-475
export function migrate(db, options = {}) {
  const { legacyStageMap = null, scopeSql = null } = options
// schema.js:592-605
if (legacyStageMap !== null) { try { … } catch {} }
if (scopeSql !== null) { try { db.exec(`UPDATE asset SET scope = (${scopeSql}) …`) } catch {} }

// store-core.js:980
migrate(handle, { legacyStageMap: LEGACY_STAGE_MAP, scopeSql: SCOPE_SQL })
```

验证（`node:sqlite` 内存库，`selfcheck.mjs` 第 3/4 项）：

| 用例 | 断言 | 结果 |
|---|---|---|
| `migrate(db, {legacyStageMap:{踩点:'recon', 边界突破:'boundary'}, scopeSql:…})` | `踩点→recon`、`边界突破→boundary`、`recon` 保持 `NULL`（不瞎猜）；`10.1.2.3→internal`、`8.8.8.8→external` | ✅ |
| `migrate(db)`（旧调用方） | 不抛错、不回填（`stage_code` 仍 `NULL`） | ✅ |
| 源文件静态 | `Object.entries(LEGACY_STAGE_MAP)` / `(${SCOPE_SQL})` 在 `schema.js` 中已 0 处；`store-core.js` 传参存在 | ✅ |

> 这类 bug 的共性是**空 `catch` 把"代码坏了"伪装成"没事发生"**。P1-5（补丁未命中即报告）要治的是同一类病，建议把"静默 catch"也纳入那条审计。

## 3. P0-3：构建链漂移闸

`client.js` 是"手写源码 + 构建产物"混排：外层 4,523 行手写、中间 4,213 行是 `__DSH_PURGE_DRILL_BEGIN__/END__` 之间的内嵌演练台。旧脚本无条件覆盖，而这份内嵌副本**比源文件新**：

```

[build-client] 检测到漂移（client.js 里的内嵌片段 ≠ lib/redteam/client.js 的构建结果）
  现存片段 sha=5b3b9916ea7c 行数=4213
  本次产物 sha=f48d403410e8 行数=4187
  首个差异在第 566 行：
    client.js  : "    }).then(async (res) => {"
    build 产物 : "    }).then((res) => res.json())"
[build-client] 拒绝写盘。…
[exit=1]
```

即：现存副本净多 26 行，首个差异在内嵌区第 566 行（≈ `client.js:4042`）——正是 `api()` 的 non-json 兜底。**旧脚本一跑就把这个修复回退掉，且没有任何提示。**

新行为（`scripts/build-client.mjs`）：

| 场景 | 行为 |
|---|---|
| 内嵌片段 == 构建产物 | 写盘（内容等价），打印 `无漂移` |
| 有差异，无 `--force` | 打印两侧 sha/行数/首个差异行，**退出码 1，不写盘** |
| 有差异，`--force` / `DSH_PURGE_BUILD_FORCE=1` | 打印"按源文件覆盖"后写盘（= 旧行为，但变成显式决定） |
| 写盘后 | 重读 `client.js` 再比一次（`:127`），不等就抛错，避免半截文件 |

顺带修掉一个隐性问题：`client.js` 是 **CRLF**（8,736 行全 CRLF），旧脚本把 LF 片段直接拼进去会写成混合 EOL；现在按文件风格转换（`:116-119`）。

## 4. P0-4：Doctor supervisor 的开关与留痕

`silenceCmdFlash`（`lib/core.js:366-405`）无条件调用 `stubDoctorSupervisor()`，它会删 `%LOCALAPPDATA%\DSH Doctor\supervisor.cmd|.vbs` 并 `schtasks /Delete /F /TN "DSH Doctor Supervisor"`（`:1191-1243`）—— 那是**另一个组件**的系统级对象，属于本插件职责之外。

改动（最小侵入：默认行为不变，只加开关 + 留痕）：

| 项 | 实现 |
|---|---|
| 开关 | `keepDoctorSupervisor(env)`（`:1171-1175`），接受 `1/true/yes/on`（大小写不敏感）；命中则 `stubDoctorSupervisor()` 返回 `{skipped:'opt_out', reason:'DSH_PURGE_KEEP_DOCTOR=1'}`，**完全不碰文件和计划任务** |
| 留痕 | `auditDoctorStub(out)`（`:1177-1189`）追加一行到 `$DSH_HOME/dsh-purge/apply-audit.log`（`DSH_HOME` 未设时回落 `~/.dsh`）：`<ISO 时间> stubDoctorSupervisor {"dir":…,"cmd":"deleted","vbs":"absent","task":"absent"}`；只在**真的删了东西或按开关跳过**时写，日常 Apply 不刷噪音（`:1241`） |
| 兼容 | `silenceCmdFlash` 返回的 `doctor` 字段形状变宽（可能没有 `dir/cmd/vbs/task`）；全仓 grep `.doctor`/`doctor.cmd`/`doctor.task` → **0 处消费**，无兼容问题 |

实测：`keepDoctorSupervisor({DSH_PURGE_KEEP_DOCTOR:'1'})=true`、`{'TRUE'}=true`、`{}=false`、`{'0'}=false`。

> 为什么不直接把默认改成"不删"：那是**行为变更**，会影响用户既有的"Doctor 不弹窗"效果（`silenceDoctorSpawnFlash` 那套配合）。先把隐式副作用变成可控项 + 可审计，是这一步的正确粒度；要不要默认关，应该由用户在面板里决定（P1 建议做成设置项）。
